# Mirror —— 基于 LLM 长期记忆的数字分身 Agent

> 一个实验性项目：复用通用记忆引擎（memory-hub），构建一个"会聊天、边聊边记住对话对象、且能用量化评测回答'它像不像本人'"的 Agent。
> 项目核心发现：**真正的难点不是"记住一个人说过什么"，而是"压制底层大模型自身的人格与知识"。**

## 概述

数字分身（digital twin / persona agent）的目标是让 LLM 复刻一个具体的人。本项目的完整链路：

```
用户 ←—对话—→ Mirror（数字分身）
                ├─ 轮前：召回相关记忆 + 画像，注入 system prompt
                ├─ 轮中：LLM 以第一人称回答
                └─ 轮末：从对话中抽取事实，写入记忆库（自动去重 / 冲突消解）
                           ↓
              memory-hub（记忆引擎：三层记忆 + 三路召回，见下文"复用说明"）
```

- **对话层**：memory-hub 只提供 write/recall 原语；本项目接入 LLM 补上对话能力
- **记忆层**：每轮结束自动抽取"关于用户"的事实入库，长期积累
- **评测层**：露馅测试（测"是否编造"）+ 盲测（测"像不像"），量化回答效果

## 核心发现

### 发现一：记忆抽取会把"现实动机"洗成"标准答案"

喂给分身一句带真实理由的话（如"我选这个方向是因为好就业"），分身复述时会说"因为更有意思、边界更模糊"。

**记忆引擎只存下了结论，丢掉了理由——抽取过程把人"现实但不够正确"的动机，规整成了"标准正确"的表述。** 这对"忠实复刻"是系统性偏差。

### 发现二：人格泄漏——模型用参数知识冒充"本人懂"

问一个从没喂过的话题，分身长篇科普、主动提供帮助。它不认为自己在编造——因为那是底层 LLM 的参数知识，不属于"关于这个人的记忆"。

**分身 = 底层模型的全部能力（脑子）+ 用户记忆（薄薄一层皮）。** 参数知识会随时越过记忆边界冒出来。

### 发现三：prompt 约束只能"盖"，不能"挖"

加入 system prompt 边界（"知识视野 = 你被喂过的"）后，越界提问会老实承认"没聊过"。

但换个问法（如让它写代码），它照样能写。**人格和知识刻在参数里，prompt 只能遮盖，无法删除。**

**结论：复刻一个人的难点，不在"记住他说过什么"，而在"压制模型自己"。**

## 理论边界：prompt+RAG 只能"演"，微调才能"成为"

由此推导出项目的技术边界：

- 本项目 = 给完整 LLM 戴上面具、喂记忆。回答永远依赖底层模型的参数能力。
- 真正的"复刻"需要**微调**：把语气、思维方式、决策习惯烧进参数。
- 与"蒸馏"同构：蒸馏是"把大模型知识压进小模型"，人格微调是"把一个人的语料压进模型"——**区别都在"动没动参数"，不在"喂没喂 prompt"**。

该结论与业界一致（见下节），本项目定位是这条路线的 MVP 验证。

## 相关工作

独立完成本设计后，调研发现该方向已有论文与产品，对表如下：

| 类型 | 代表 | 关系 |
|---|---|---|
| 论文 | [*Towards the "Digital Me"*](https://arxiv.org/abs/2506.23826)（arXiv 2506.23826）| **同一条技术路线**：prompt-based 系统架构，LLM + 增强型 RAG，未做微调 |
| 论文 | LD-Agent（NAACL 2025）| 事件记忆 + 双向人格建模 |
| 学术方向 | persona-based LLM（PersonaAgent / PICLe / DEEPER 等）| PICLe 用 3-10 个 few-shot 样例达到 88%-93% 一致率 |
| 产品 | Replika / CarynAI / 硅基智能等 | 网红微调自己、粉丝付费对话，商业化已跑通 |

**与 arXiv 2506.23826 的对比**：同路线（prompt + RAG，无微调）。对方多出三维检索加权、记忆强化/衰减模拟、反思固化、两阶段生成；本项目差异点在于**通过行为评测（泄露审计、盲测）系统性暴露了 prompt 路线的失效模式**。

## 踩坑记录（M1-M10）

| # | 现象 | 根因 |
|---|---|---|
| M1 | 精确字段（学校名）召回不到 | 未接向量时三路召回全空退化 |
| M2 | 历史记忆成"孤儿向量" | 写入时 vec_stale 硬编码 0，永不补嵌 |
| M3 | 自我介绍类信息被漏存 | 抽取器"宁可漏"策略过于激进，无兜底 |
| M4 | 评测误判"编造" | 判据用整串匹配，措辞一变即漏 |
| M5 | 闲聊中顺嘴泄漏未喂过的偏好 | 约束管"行为"不管"判断"，且模型会自行圆场 |
| M6 | 审计员把常识缩写误判为泄露 | LLM 审计缺乏缩写等价（"北交"=北京交通大学）的常识 |
| M7 | 玩梗问候被答"没聊过" | 约束把"知识断言"和"社交玩梗"一刀切 |
| M8 | 全程一个温度，语气呆板 | 无关系设定 + 记忆中无"说话温度"样本 |
| M9 | 语气写死，跟不上用户变化 | 抽取器无"说话方式"类别，语气只能靠 few-shot |
| M10 | 盲测"关键词命中"测不出"像不像" | "像不像"在语义层不在用词层，硬指标只能测"是否记住原词" |

**评测方法论的教训**：对生成类 Agent，"关键词匹配"式硬指标测不出行为相似度，需叠加 LLM 盲判；而 LLM 审计本身又会引入 M6 式误判——**评测器也需要被评测**。

## 快速开始

```bash
# 1. 对话：运行「和镜像聊天.bat」（每轮结束打印 [记住] xxx）
# 2. 评测：运行「跑盲测.bat」，对比喂料前后基线
```

对话中：`/记忆` 查看已存记忆，`/画像` 查看用户画像，`q` 退出。

## 复用说明：memory-hub

记忆引擎基于开源项目 [memory-hub](https://github.com/redmaplewww/memory-hub)（作者 redmaplewww）二次开发。

- **复用**：三层记忆（画像 / 条目 / 会话摘要）+ 冲突消解 + 三路 RRF 召回 + 事件审计内核
- **本项目改动**：
  - 接入 DashScope `text-embedding-v3` 替换原 fastembed，修复 M1（召回退化）、M2（孤儿向量）两个缺陷
  - 新增 `style` 记忆类别，使语气/口头禅成为可生长、可冲突消解的记忆
  - 调整抽取器"宁可漏"策略，补充自我介绍类信息漏存兜底
- **协议说明**：原仓库未附带 LICENSE，遵循"保留出处、如实声明改动"原则，具体改动见 `memory_hub/README.md`

## 技术栈

- 记忆引擎：memory-hub（复用，零第三方依赖，三层记忆 + 冲突消解 + 三路 RRF 召回）
- LLM：DeepSeek（对话 + 抽取 + 冲突消解）
- Embedding：DashScope text-embedding-v3
- 评测：露馅测试（编造率）+ 盲测（关键词硬指标 + LLM 盲判软指标）

## 文件结构

```
mirror.py        镜像本体：对话循环 + 短期记忆 + 边聊边记 + 人格约束

evaluate.py      露馅测试（是否编造）
blind_test.py    盲测（行为相似度）
blind_questions.py  盲测题目与评测集
memory_hub/      复用的记忆引擎
DESIGN-MIRROR.md 工程设计与踩坑记录（M1-M10）
```
